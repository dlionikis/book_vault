## 2. Decision: Integrate Now vs. Defer

### **RECOMMENDATION: Integrate Now**

**Reasons to integrate**:

1. **Component Count**: 18+ components already built → Storybook will provide immediate value for component catalog and testing
2. **Server Component Complexity**: Next.js App Router + Server Components require careful Storybook configuration → better to set this up now before component count grows
3. **Dark Mode Testing**: `next-themes` integration needs visual testing → Storybook is ideal for testing dark/light variants
4. **AI-First Development**: Documentation-first approach aligns perfectly with Storybook's self-documenting nature
5. **API-Ready Architecture**: Many components will need mock data → Storybook's MSW integration will help visualize components without backend

**Risks of deferring**:

- More components = harder migration later
- Server Component patterns will be harder to retrofit into stories
- Testing dark mode variants manually is error-prone

### **AI-Assisted Development Benefits** ⭐

Storybook integration will **dramatically improve Claude Code effectiveness**:

1. **Token Reduction**: 50-85% fewer tokens per component exploration
   - Today: Read component + types + parent usage = ~1,000 tokens
   - With Storybook: Read story file = ~150 tokens

2. **Faster Iteration**: 10x speed improvement for UI changes
   - Today: Start dev server → navigate → test = 2-3 minutes
   - With Storybook: Open story → instant visual feedback = 10 seconds

3. **Self-Documenting Props**: No more type hunting across files
   - Story args show exact prop shapes with examples
   - Edge cases documented as story variants

4. **Zero-Ambiguity Context**: Each story shows ONE component state clearly
   - Long titles, missing images, loading states all documented
   - Dark mode variants visible instantly

**Expected Impact**: Future feature requests will require 50-80% fewer tokens and produce more accurate first-try implementations.

1. Create `docs/component-guide.md`:

   ```markdown
   # Component Selection Guide

   > Quick reference for choosing the right component. Read this FIRST before exploring components.

   ## "I need to show a book" → Which component?

   - **Grid/list of books** → `BookGrid` (handles layout + responsive grid)
     - Props: `books: Book[]`, `showProgress?: boolean`
     - Use when: Home page, search results, browse pages

   - **Single book card** → `BookCard` (individual book display)
     - Props: `book: Book`, `showProgress?: boolean`
     - Use when: Inside BookGrid or custom layouts

   - **Book with play button** → `BookCard` + `ContinueListeningButton`
     - Only if user has progress on this book
     - ContinueListeningButton handles routing to playback

   ## "I need audio playback"

   - **Full playback page** → `PlaybackClient` (full-featured player)
     - Location: `app/books/[id]/play/page.tsx`
     - Handles: Progress tracking, chapter nav, Media Session API
     - Props: `book: Book`, `audioUrl: string`, `initialPosition?: number`

   - **Embedded player only** → `AudioPlayer` (needs external state)
     - Requires: Parent to manage progress saving
     - Props: `audioUrl: string`, `initialPosition?: number`, `onProgress?: (pos) => void`

   ## "I need navigation/UI controls"

   - **Back button** → `BackButton` (uses router.back())
   - **Pagination** → `Pagination` (handles page state)
   - **Search input** → `SearchBar` (client component with debounce)
   - **Theme toggle** → `ThemeToggle` (dark/light mode)
   - **User menu** → `UserMenu` (dropdown with logout)

   ## "I need to show progress/status"

   - **Progress badge on book** → `ProgressBadge` (shows % or "Completed")
   - **Progress controls** → `ProgressControls` (mark complete/reset buttons)
   - **Progress status text** → `ProgressStatus` (human-readable text)

   ## Server vs Client Components Quick Ref

   **Client Components** (have 'use client'):

   - `AudioPlayer`, `PlaybackClient`, `SearchBar`, `ThemeToggle`
   - `AddToLibraryButton`, `ContinueListeningButton`, `UserMenu`
   - `SessionProvider`, `ThemeProvider`

   **Can be either** (no interactivity):

   - `BookCard`, `BookGrid`, `Pagination`, `ProgressBadge`
   - `BackButton`, `ChapterList`, `SortDropdown`

   **Rule**: Only add 'use client' if component uses hooks (useState, useEffect, etc.)
   ```

   ```markdown
   # Data Flow Patterns

   > Shows how data moves through the app. Use this to understand where to fetch/modify data.

   ## Flow 1: Playing an Audiobook (Full Flow)
   ```

   User clicks "Play" on BookCard
   ↓
   BookCard → router.push(`/books/${book.id}/play`)
   ↓
   app/books/[id]/play/page.tsx (Server Component)
   → Fetches book from DB: prisma.book.findUnique()
   → Passes to PlaybackClient as props
   ↓
   PlaybackClient (Client Component)
   → On mount: Fetches progress via GET /api/progress?bookId=X
   → Renders AudioPlayer with initialPosition
   ↓
   AudioPlayer
   → Plays audio from audioUrl
   → Every 10s: Saves progress via POST /api/progress
   → On unmount: Final progress save

   ```

   **Files involved**:
   - `components/BookCard.tsx` (trigger)
   - `app/books/[id]/play/page.tsx` (data fetch)
   - `components/PlaybackClient.tsx` (state management)
   - `components/AudioPlayer.tsx` (playback)
   - `app/api/progress/route.ts` (persistence)

   **To modify playback**: Usually edit `PlaybackClient.tsx` or `AudioPlayer.tsx`
   **To modify progress tracking**: Edit `app/api/progress/route.ts`

   ## Flow 2: Searching for Books

   ```

   User types in SearchBar
   ↓
   SearchBar (Client Component)
   → Debounces input (500ms)
   → router.push(`/search?q=${query}`)
   ↓
   app/search/page.tsx (Server Component)
   → Reads query from searchParams
   → Fetches results: GET /api/search?q=query&limit=50
   → Renders BookGrid with results
   ↓
   BookGrid → Maps books to BookCard components

   ```

   **Files involved**:
   - `components/SearchBar.tsx` (input)
   - `app/search/page.tsx` (results page)
   - `app/api/search/route.ts` (search logic)
   - `components/BookGrid.tsx` (display)
   ```

   User clicks "Add to Library" button

   → Returns 201 Created
   ↓
   Page re-renders with updated library status

   ````

   **Files involved**:
   - `components/AddToLibraryButton.tsx` (trigger)
   ````

   ````markdown
   # API Endpoints Quick Reference

   > Copy-paste reference for API calls. Shows exact request/response shapes.

   ## Books

     page: number,
   ````

   **Response**: `{ book: Book }` (includes authors, narrators, series)

   ### GET /api/books/[id]/chapters

   **Response**: `{ chapters: Chapter[] }` (ordered by chapterNumber)

   ## Progress (Authenticated)

   ### GET /api/progress?bookId=[id]

   **Response**:

   ```typescript
   {
     positionSeconds: number,
     completed: boolean,
     lastPlayed: string (ISO date)
   }
   ```

   **Returns 404 if no progress**

   ### POST /api/progress

   **Body**:

   ```typescript
   {
     bookId: string,
     positionSeconds: number,
     completed?: boolean
   }
   ```

   **Response**: `{ success: true, progress: UserProgress }`

   ## Library (Authenticated)

   ### GET /api/library

   **Response**: `{ books: Book[] }` (user's added books)

   ### POST /api/library

   **Body**: `{ bookId: string }`
   **Response**: `{ success: true }` (201 Created)

   ### DELETE /api/library?bookId=[id]

   **Response**: `{ success: true }` (204 No Content)

   ### GET /api/library/check?bookId=[id]

   **Response**: `{ inLibrary: boolean }`

   ## Search

   ### GET /api/search?q=[query]&limit=[limit]

   **Query params**: `q: string` (required), `limit?: number` (default 50)

   ```typescript
   {

   }
   ```
